# Backend design

FastAPI + Motor (MongoDB). One image runs as web or worker.

## The one rule: everything is an action

Every change goes through one function in the action registry (`backend/app/domain/`). Each action has:

- a **level**: read, internal, external (leaves the app), money, destructive
- the **roles** allowed to run it
- a plain input model

Four doors call the same actions, so rules are checked once:

| Door | Where |
|---|---|
| Screens | `POST /api/a/<name>` |
| Automations | `app/automations/engine.py` |
| Agents | `app/agents/runtime.py` (tool names use `__` for `.`) |
| AI connector | `app/api/routes/mcp.py` (JSON-RPC) |

Full list: `docs/API_CONTRACT.md` (generated by `scripts/gen_docs.py`).

## Tenants

Every practice is a workspace. Actions read and write through `ctx.data.<collection>`, which adds `workspace_id` and hides soft-deleted rows. A test fails if an action touches a tenant collection directly.

## Safe without transactions

MongoDB multi-document transactions are not used. Double sends and double payments are stopped by unique keys:

| What | Key |
|---|---|
| Payment on a schedule item | `payments._id = invoice:item` |
| Ledger row | `ledger.key` |
| Outgoing message | `outbound_queue.idempotency_key` |
| Approval | `approvals.idempotency_key` |
| Automation run | `automation_runs.run_key` |
| Booked slot | `slot_locks._id = host|start` |
| Invoice number | `invoices.number_key` |
| Whole-invoice save | `invoices.rev`: saved only over the revision it was read at, else re-read and retried |
| Budget cycle and its alerts | `budget_cycles.cycle_key`, alerts added only if not already sent |
| Retainer period | `retainer_periods.period_key`; close claimed open → closing → closed |
| Checklist and repeating tasks | `tasks.occurrence_key` |
| Estimate accepted | estimate claimed `final` → converting, once |
| OAuth code, tokens | `oauth_codes.code_hash`, `oauth_tokens.token_hash`; a reused code or refresh token revokes its chain |

If two workers race, one insert wins and the other gets "already done".

## Events

Actions write events to an outbox. The dispatcher (every few seconds) takes each event once and:

1. moves the project stage forward (never backward)
2. wakes automation runs waiting for that event
3. starts matching automations
4. starts the meeting agent on new transcripts

## Automation runs

- A run stores a snapshot of the steps, so editing an automation never changes runs in flight.
- A path pointer walks nested yes/no branches.
- Waits set `wake_at`. The tick claims due runs with a lease and runs 25 at a time.
- Send steps can need approval. The run pauses until the consultant approves or skips.
- "Why didn't this run?" checks each reason in order and answers in one line.

## Agents

- Tool-use loop over the action registry. `gate()` decides per call: run, ask for approval, suggest only, or refuse.
- Modes: draft (everything waits for OK), ask, auto. Money always needs a person.
- Actions marked `sensitive` (`workspace.update`, `team.add`, `team.update_role`) always need a person too, in every mode and over MCP.
- AI budget per workspace per month (`ai_cost_cap_paise`, default ₹400, set in Admin), and at most ₹25 per run.
- Client text, and every tool result, is wrapped in `<client_data>` and treated as data, never instructions.
- QA mode uses scripted plans, so tests and demos run without an API key.

## Limits

`app/core/limits.py` holds every plan limit with a default. Admin changes go to the `limit_values` collection and take effect within 60 seconds. A change can apply to all accounts or only accounts created from now on. Per-account overrides can have an end date. Every change is logged and can be reverted.

## One filter for money and cost

Every action result goes through one filter on its way out, whichever door it leaves by (screens, API, chat, agents, MCP):

- roles with money hidden: amounts become empty
- anyone who may not see costs (Members, Collaborators, Managers unless the Owner allows it): every `cost…` and `margin…` field is removed

Sorting or filtering by a hidden field is refused, not answered.

## Add-on modules

| Module | What |
|---|---|
| `app/domain/billing/rates.py` | Services, rate cards, scheduled changes, cost per hour, `resolve()` and the snapshot stored on each time entry |
| `app/domain/billing/timebill.py` | Time entries, week grid, timer, billing status, lock, unbilled time onto invoices, bulk invoice actions |
| `app/domain/billing/budgets.py` | Budgets, cycles, alerts, forecast, task estimates |
| `app/domain/billing/retainers.py` | Retainers, periods, close, statements; checklists and repeating tasks |
| `app/domain/billing/estimates.py` | Estimates, quick quotes, proposals from estimates, conversion on acceptance |
| `app/domain/analytics/insight.py` | Forecast, profit and effective rate, utilisation |
| `app/domain/engagement/client_tasks.py` | Client tasks, reminders, overdue |
| `app/api/routes/oauth.py` | MCP sign-in (OAuth 2.1, PKCE, CIMD, DCR, RFC 9728/8414/8707/9207) |

Time lines on invoices keep their minutes: line total = minutes × hourly rate ÷ 60, plus the paise that make the total exact. So grouping never changes the total.

## Money

- Amounts are integer paise. No floats.
- Clients pay outside the app (UPI or bank). They tap "I've paid"; the consultant confirms. That creates one ledger row.
- Numbers have no gaps per financial year: assigned only when an invoice is issued.
- Paid invoices are locked. Changes go through credit notes.

## Jobs

APScheduler in the worker (`python -m app.workers`). Each job takes a lease (`app/db/locks.py`) that is renewed while it runs, so two workers never run the same job at once. Scans stream cursors; per-workspace jobs run a few workspaces at a time (`JOB_WS_CONCURRENCY`). Runs are logged in `job_runs` and visible in Admin → Jobs.

| Job | When |
|---|---|
| dispatch events | every 10 s |
| automation tick | every 30 s |
| outgoing messages | every 30 s |
| session holds and reminders | every 1 min |
| inbox lead finder | every 15 min |
| money (overdue, late fees, reminders) | hourly |
| housekeeping (expired approvals, old codes) | hourly |
| project start/end dates | 07:30 IST |
| daily brief | 07:45 IST |
| follow-up agent | 08:00 IST |
| recurring invoices | 09:05 IST |
| collections agent | 10:00 IST |
| budgets (resets, alerts) | hourly |
| retainers (close periods, renewals) | hourly |
| repeating tasks | hourly |
| client task reminders and overdue | hourly |
| invoice ZIPs | every 1 min |

## Client pages

Served by a small separate bundle (`client.html`) at `/c/<practice>/...`, on `<practice>.<CLIENT_DOMAIN>`, or on a custom domain mapped in Admin.

## Vendors

`app/integrations/vendors.py` has a fake and a live version of each outside service. `VENDOR_<NAME>=live|fake|off`. QA mode forces fake.
